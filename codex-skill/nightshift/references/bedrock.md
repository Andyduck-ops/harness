# Bedrock — 不可修改的第一性原理

这些原理是 nightshift 验证所有 findings 的基准线。
如果 finding 与这些原理冲突，标记 `[BEDROCK_CONFLICT]` 而不是写入 patterns。

---

## P1: 仓库是唯一的大脑

知识必须在仓库里，版本化，机器可读。
不在仓库里的知识 = 不存在。

## P2: 强制执行 > 行为建议

Hooks / linters / CI 强制执行的规则 > 文档里写的"请遵守"。
人和 AI 都会忘记建议，但绕不过自动化检查。

## P3: 按需精确注入

全量知识库太大，必须按阶段/任务/角色精确注入上下文。
JSONL 机制就是这个原则的实现。

## P4: 人守门在高杠杆点

自动化做重复性工作，人做不可逆的判断。
高杠杆点 = 需求定义、架构决策、知识批准。

## P5: 先做能用的，数据驱动升级

不预设计完美方案。先跑起来，用数据（adoption rate, failure rate）决定是否升级。

## P6: 知识复利是最大杠杆

每次工作都应该改善系统本身。静态系统几周内就会腐烂。

## P7: Agent 缺陷是架构性的

Agent 的幻觉、窗口限制、感知黑盒、死循环——
这些是架构缺陷，不是"不够聪明"。
教训应该按缺陷类型（ANCHOR/SHAPE/DECODE/ESCAPE）组织。

## P8: 世界是运动与变化的

知识会过时，工具会更新，最佳实践会演变。
系统必须有自我更新的能力，否则会被时间淘汰。
