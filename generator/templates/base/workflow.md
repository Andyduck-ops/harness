# Development Workflow

> Auto-generated by Harness. Customize for your project.

## Core Principles

1. **Read Before Write** — Always read existing code before modifying
2. **Specs are Injected** — Hooks auto-inject specs; don't manually load them
3. **Evidence-Based Iteration** — Every change must produce verifiable evidence
4. **Failure Budget** — Max 3 same-type failures before escalation

## Verification Commands

- **Test**: `_PLACEHOLDER_TEST_CMD_`
- **Lint**: `_PLACEHOLDER_LINT_CMD_`
- **Build**: `_PLACEHOLDER_BUILD_CMD_`

## Pipeline Stages

```
plan → implement → check → [debug ≤3] → finish → PR
```

| Stage | Agent | Reads | Writes |
|-------|-------|-------|--------|
| plan | plan | user input | prd.md |
| implement | implement | prd.md + specs (injected) | code + agent-outputs/implement-result.md |
| check | check | code + verify commands | agent-outputs/check-result.md |
| debug | debug | check failures | fixes + agent-outputs/debug-result.md |
| finish | finish | all agent-outputs/ | PR description |

## Task Lifecycle

1. `/harness:start` — Initialize session, detect/create task
2. Research → configure JSONL context
3. Implement → hooks inject specs automatically
4. Check → quality gate enforces verify commands pass
5. `/harness:compound` — Extract lessons after completion
