# Execution Model — Agent 生命周期与权限体系

## Agent 执行生命周期

### Phase 1: 边界确认（Before Execution）

每个任务启动前必须明确：

| 项目 | 内容 | 示例 |
|------|------|------|
| **交付物** | 任务完成时产出什么 | "修复登录页 500 错误，测试通过" |
| **成功标准** | 如何判断完成 | "npm test 全绿 + 手动验证登录流程" |
| **约束** | 不可变范围 | "不改动数据库 schema" |
| **验证命令** | 用什么证明完成 | `npm test`, `npm run lint`, `curl -I /login` |
| **失败预算** | 允许失败几次 | "同类失败 ≤3 次，超出升级" |

### Phase 2: 自主执行（Controlled Autonomy）

在预算内，Agent 自主循环：



**关键约束：**
- 每次迭代必须产出证据（P8）
- 无证据重试被禁止
- 策略不变的重试最多 1 次

### Phase 3: 交付收束（Traceable Delivery）

每个任务结束时必须输出：

1. **变更清单**：修改了哪些文件，关键行为变化是什么
2. **验证证据**：运行了什么命令，结果是什么，失败-修复历史
3. **已知风险**：未覆盖的边缘情况，已知限制
4. **知识产出**：本次任务发现的可复用教训（如有）

严禁：静默降级、假成功路径、隐藏失败。

## 4 级权限阶梯

| 级别 | 能力 | 触发升级 | 回退条件 |
|------|------|---------|----------|
| **L1 只读** | 读代码、读文档、搜索 | 需要运行测试时 | — |
| **L2 测试** | 运行测试、静态分析、lint | 需要修改代码时 | 测试引入新失败 |
| **L3 修改** | 编辑代码、运行回归测试 | 需要外部操作时 | 回归测试失败 |
| **L4 外部** | 发布、生产操作、网络请求 | — | 人工显式授权 |

### 升级协议



### EHRB 高风险检测（L3/L4 守卫）

5 类正则检测（从 SPARV 移植）：

| 风险类 | 检测模式 | 处理 |
|--------|---------|------|
| **E**nvironment | 修改环境变量/配置 | 二次确认 |
| **H**igh-impact | 删除/重命名核心文件 | 阻塞+人工审批 |
| **R**eversibility | 不可逆操作（DROP TABLE, rm -rf）| 阻塞+人工审批 |
| **B**oundary | 跨越安全边界（网络/权限/支付）| 阻塞+人工审批 |
| **S**cope | 修改范围超出任务定义 | 警告 |

### 各阶段 Agent 职责

| 阶段 | Agent | 输入 | 输出 | 验证 |
|------|-------|------|------|------|
| **plan** | plan agent | 用户需求 | prd.md（含成功标准 + 边界 + 命令）| 人工审批 |
| **implement** | implement agent | prd.md + spec + lessons | 代码变更 + agent-outputs/implement-result.md | 自动 |
| **check** | check agent | 代码 + 验证命令 | 测试结果 + agent-outputs/check-result.md | quality-gate |
| **debug** | debug agent | check 失败证据 | 修复 + 新测试 | ≤3 次上限 |
| **finish** | finish agent | 全部 agent-outputs | 变更摘要 + PR 描述 | 自动 |

## 求助协议（Structured Escalation）

### 触发条件

| 条件 | 示例 |
|------|------|
| 同类失败 ≥2 次 | lint 反复报同一类错误 |
| 缺少关键上下文 | 不知道数据库连接方式 |
| 需要 L4 权限 | 要部署到生产环境 |
| 多方案需权衡 | 两种修复方案各有利弊 |

### 求助消息格式



人确认后，Agent 立即继续执行，不再重新讨论。
全过程记录到任务日志，保证可追溯。
